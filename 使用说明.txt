论文检索 · Thesis Browser 1.0.6
2026-11-15

这是非官方的清华大学学位论文检索辅助客户端，不代表清华大学或图书馆。

一、Windows 直接使用

双击 release 文件夹中的 ThesisBrowser-1.0.6-win-x64.exe，无需安装 Python、Node.js 或浏览器运行库。
也可从公开的 https://github.com/wangyendt/thu-thesis-browser/releases/latest 下载。
首次启动便携版需要解压运行组件，速度取决于磁盘和安全扫描。不要反复双击。
程序未购买代码签名证书，系统可能显示未知发布者。可检查源代码并自行构建。

上方填写：学号包含 2022；学科/专业 工程管理；勾选“专业精确匹配”；点击“检索论文”。
2026-11-15 在独立未登录会话下实测返回 71 篇。数据数量会随网站更新。
也可使用网页内原有的高级检索、日期、学位、排序及数据库切换功能。
点击论文标题会在内嵌新标签页打开，不会丢失原来的检索列表。

二、浏览、登录、下载

在网页上按原流程登录、预览或下载。权限由网站决定，可能需要清华账号、校园网或 VPN。
本工具不会绕过登录、验证码、下载次数或访问权限，也不批量抓取全文。
登录状态保存在本机，与 Chrome/Edge 的登录状态独立；首次使用需要重新登录。
打开论文 PDF 预览，点击右上角“保存当前 PDF”。客户端会先直接弹出系统“另存为”窗口，选择路径后再读取并写入 PDF。
建议从论文详情页进入预览，默认文件名为：论文题目_姓名_学院或培养单位_专业_学位_答辩日期.pdf。
缺失字段自动跳过，过长名称会截短，非法字符会替换；你仍可在“另存为”中修改名称。
文件名不包含完整学号或掩码学号，按学号检索的功能不变。直接打开 PDF 链接时若没有详情信息，会退回 PDF 自带标题、作者或原始文件名。
右上角“下载记录”只管理任务，不会触发保存。非 PDF 页不能保存；在预览页不再依赖后台就绪检测来解锁按钮。
首次显示首页不代表完整 PDF 已加载，保存时可能需要等待其余数据。读取和写入状态会显示在按钮、底栏及任务列表中，失败会说明原因。
保存当前已获准加载的文档，字节内容及原有水印保持不变；不会猜测签名、请求其他用户的文档或获取无水印版。
读取完整文档可能需要继续加载尚未读取的页面。网络失败或会话失效时，客户端会显示错误，不会把登录页面存成 PDF。
清华域名下的窗口保留在客户端，外部链接经确认后由系统浏览器打开。
如第三方身份认证只能使用外部网站，客户端与外部浏览器的会话不互通，可能无法完成该流程。

三、数据与安全

不设置云同步或分析遥测，不记录密码。检索条件和下载目录保存在本机 settings.json。
网站 Cookie/缓存保存在操作系统应用数据目录中的 Thesis Browser 会话存储内。
在共享电脑上请使用网站退出登录。若需要清理所有会话，可关闭程序后在系统应用数据目录定位本应用并自行删除其数据。
网页禁用 Node.js，启用沙盒和上下文隔离；本地工具栏与远程网页之间没有通用文件读写桥接。
只对 newetds.lib.tsinghua.edu.cn 的 qhGetSingleList 检索请求修正字段。
不忽略 HTTPS 证书错误，不更改网站的认证请求。PDF 保存使用当前预览器的已加载文档，不重放签名 URL。

四、为什么能检索

网站页面把“学科名”提交为 conditionKey="学科名"，目前接口对应字段却是“专业”。
客户端自动把检索请求的该字段改为“专业”，保留学号、匹配方式及其他条件。
不是给搜索词增加 %、* 或引号。网站修复或修改接口后，本工具也可能需要更新。

五、从源代码运行和构建

本项目现为独立 Git 仓库 D:\work\code\latex\thu-thesis-browser。原论文仓库中的 tools/thu-thesis-browser 保留为备份。使用 Node.js 24 或更高版本。
在本目录打开终端：

  npm ci
  npm start

打包命令（在对应操作系统执行）：

  Windows x64：npm run dist:win
  macOS Intel 和 Apple Silicon：npm run dist:mac
  Linux x64：npm run dist:linux

产物位于 release。macOS 和 Linux 构建脚本已配置，但本机是 Windows，未在这两个系统上实测。
macOS 构建没有 Apple 开发者签名或公证；对外分发需要自行配置签名、公证。
Linux 需要桌面图形环境和发行版提供的 Electron 系统依赖。AppImage 可能需要 FUSE 支持。
仓库根目录 .github/workflows/build.yml 提供手动触发的三平台构建工作流。
公开源码仓库：https://github.com/wangyendt/thu-thesis-browser，默认分支 main。
推送代码不会自动运行构建工作流。

若开发依赖下载很慢，请使用自己信任的网络代理。Node.js 24+ 可通过 NODE_USE_ENV_PROXY=1 让内置 fetch 使用 HTTP_PROXY/HTTPS_PROXY。
Electron 安装也支持 ELECTRON_GET_USE_PROXY。依赖版本和完整性信息保存在 package-lock.json。

七、1.0.1 修复

旧版“下载”只显示任务，无法保存当前预览。网站预览器的保存按钮又被全局 CSS 隐藏，导致用户没有可用入口。
新版增加“保存当前 PDF”，并把旧入口改名为“下载记录”。PDF 尚未加载、数据异常、文档切换等情况会阻止错误保存。

八、1.0.2 修复

1.0.1 仍依赖浏览器的 blob 下载自动弹窗，并用后台就绪探测禁用按钮。新版取消这两项依赖。
改为客户端先调用带父窗口的系统“另存为”对话框，再读取当前已加载 PDF 的原始字节，由主进程安全写入文件。
取消对话框不会读取全文或创建文件。临时写入完成后才替换目标文件；读取、网络或磁盘错误会显示“保存失败”。
2026-11-15 已在 Windows 原生对话框中实际点击保存，并验证生成文件与水印测试文档字节一致；不是仅模拟对话框返回值。

九、1.0.3 根因修复

在用户实际运行的便携版中复现到 Untrusted IPC sender：Node 把 Windows 短路径 ADMINI~1 编码为 ADMINI%7E1，而 Chromium 保留 ~，导致工具栏命令被拒绝。
改为比较解码后的精确文件路径。仍要求命令来自本地工具栏 webContents 和其主框架，远程网页、其他文件及子框架不能调用。
命令调用失败会在底栏提示，保存按钮不再因为一次 IPC 失败永久禁用。
已在实际用户会话中验证：恢复按钮、弹出另存为、保存当前 153 页论文。当前会话的临时修复在退出后结束，请使用 1.0.3 获得持久修复。
打包回归测试覆盖了包含 ~ 的安装目录，不只测试源码运行模式。命令行 --user-data-dir=绝对路径可用于独立测试配置，不会借用用户的登录状态。

十、1.0.4 独立仓库与图标

迁入独立 Git 仓库，不包含旧版发布包、登录缓存或真实论文文件。旧目录不删除。
新增书页与放大镜图标，统一 EXE、便携启动器、窗口、任务栏与应用内标识。图标源文件位于 assets/icon.svg，执行 npm run icons 可重新生成。
ICO 包含 16、20、24、32、40、48、64、128、256 像素尺寸，另有 PNG 和 macOS ICNS。
Windows 开启 EXE 图标及版本资源编辑，单独关闭代码签名。程序仍未签名，不需要以管理员身份运行。

十一、1.0.5 论文信息命名

从当前论文详情页读取题目、作者、学院或培养单位、学号、专业、学位和答辩日期，组成“另存为”的默认文件名。
进入新预览标签页时保留该论文的信息快照；原详情页关闭或跳转不会改变文件名，切换到其他 PDF 会清除旧信息。
只更改文件名，不改写 PDF 字节或水印。缺失、未公开的字段跳过，不使用登录表单中的姓名、学号，也不补全网站掩码。
文件名按 UTF-8 字节限制长度，保留原子写入临时文件的空间，兼容 Windows、macOS 和 Linux 的常见文件系统。

十二、1.0.6 去掉文件名学号并发布

自动命名不再加入学号，详情命名元数据也不再保留该字段。按学号检索、其他命名字段和 PDF 保存流程保持不变。
GitHub Release 提供 Windows x64 便携版、源码 ZIP 和 SHA256 校验文件。仓库及 Release 均公开，可直接下载。
